# Platform Routing

Load after platform/posture is known. Keep one brand DNA across platforms, but create a separate Master whenever composition or interaction changes.

| Posture | Composition | Narrative guidance | Core extras |
| --- | --- | --- | --- |
| iPhone/iPad | Device-frame + headline + background is allowed; frame pixels must remain locked. Re-layout iPad rather than stretching iPhone. | Phone usually 3–10, default 6; tablet may be denser. | Icon; iPad set if scoped. |
| macOS | Real app window/window chrome on restrained backdrop; no hardware frame. | Fewer, denser workflow/multi-window screens. | Mac icon if scoped. |
| tvOS | Full-bleed authentic TV UI; no device frame; focus state and 10-foot legibility. | Usually 3–4 content-forward screens. | Genuine tvOS layout. |
| watchOS | UI-only exact watch canvas; no frame, caption, decorative background, or mobile arc. | Usually 2–4 core states/complications. | Consistent watch generation per localization. |
| visionOS | Flat capture of the real spatial/windowed view; not stereoscopic output. | Usually 3–5 screens proving spatial value. | Show depth/windowing/immersive distinction truthfully. |
| Android phone | Authentic UI dominates; captions remain minor; consistent portrait or landscape. | 2–8 allowed; plan at least 4 strong discovery screens when appropriate. | Icon + mandatory Feature Graphic. |
| Android tablet/Chromebook | Authentic large-screen UI; landscape or portrait chosen for real use; no phone stretch. | Usually at least 4 meaningful large-screen views. | Separate tablet sizes; Chromebook landscape. |
| Android TV | Full-bleed genuine TV UI, no frame, 10-foot legibility. | Lean-back/focus-navigation story. | At least one screenshot + TV banner. |
| Wear OS | Square UI-only capture; critical content centered for round-display crop. No frame/text/graphics/background/mask. | Core watch state; include Tile/face variants when useful. | At least one current app/face screenshot. |
| Automotive/XR | Use authentic posture-specific UI; requirements evolve. | Prove context-specific value, not phone reuse. | Verify current console rules before production. |

## Android-specific content rules

- Use JPEG or 24-bit PNG without alpha for screenshots/Feature Graphic/TV banner; use the icon format specified in `canvas-specs.md`.
- Never add CTA (“Install now”), rank/accolade/download counts, price/promotion, time-sensitive claims, or testimonials without verified approval and current policy compatibility.
- Clean notifications, carrier clutter, and accidental status states.
- Write concise alt text for every preview asset, preferably under 140 characters, describing the meaningful state without “image of”.
- Feature Graphic is a banner, not a screenshot crop: keep focal content central, allow overlay/crop safety, avoid edge-critical copy, fine detail, obsolete device imagery, and pure white/black/dark-gray fields that disappear into store surfaces.
- Google Play promo video uses a public/unlisted embeddable YouTube URL, ads off, not private/age-restricted. Show authentic experience early; aim for most of the video to be real product use. Feature Graphic may receive a play overlay.
- Google Play short description is required for publishing but belongs to opt-in copy scope here: maximum 80 characters; plain core purpose; no CTA, rankings, promotions, decorative characters, keyword stuffing, emojis, repeated punctuation, or emphasis capitalization.

## Multi-platform rule

Do not imply that a complete phone set covers other postures. Track each independently in the final summary. Brand palette, typography voice, and mood may carry across; canvas, composition, UI posture, narrative length, and export rules may not.
