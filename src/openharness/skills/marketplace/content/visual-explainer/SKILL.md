# 视觉解释图

## 路由

先判断用户要传达的是流程、层级、对比、时间线、空间关系还是界面布局，再选择白板图、信息图、流程图、思维导图、演示页或 UI 线框图。内容超过一张图能清晰承载的范围时，建议拆成多帧或多页，而不是缩小文字。

## 工作流

1. 提取主题、受众、阅读顺序、关键节点、关系、数据来源、语言和用途。缺少内容时先询问，不凭空补事实。
2. 建立信息骨架：标题、主路径、分组、连接关系、重点标注和次要说明；复杂主题控制在 5–12 个核心概念。
3. 选择视觉风格与画布方向。白板/草图强调手绘层级，信息图强调分区与图例，UI 线框图强调组件关系和设备安全区。
4. 先输出低保真版式草案和文字层级，让用户确认信息结构；确认后再交给图片生成能力制作视觉稿。
5. 生成后检查阅读顺序、箭头方向、图例、对比关系、文字可读性和空白；精确数字、长段文字和 Logo 建议后期叠加。
6. 交付视觉稿、结构化文案、版式说明和后期排版清单；需要多页时保持统一网格和色彩锚点。

## 质量与安全

- 不捏造数据、引用或产品功能；不把模糊关系画成确定因果。
- 每个节点只表达一个概念，连线必须有方向或关系说明。
- 涉及医疗、金融、法律或安全决策时，标明信息来源和“仅供说明”边界。
- 图片生成、artifact 注册和文件权限由后端负责，技能不直接访问外部服务或密钥。
