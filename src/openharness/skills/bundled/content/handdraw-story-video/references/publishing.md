# BGM、预览与发布文案

这个参考文件把本地制作管线中的 BGM、预览、渲染、FFmpeg 和抖音发布经验，改写为 SaaS 内置 Skill + 官方后端 Tool 的工作方式。

## BGM 策略

- 默认可以输出无声 MP4。
- 用户明确要求 BGM，或故事气质明显适合轻柔背景音乐时，优先选择后端内置曲库 mood。
- 曲库曲目由 SaaS 后端 manifest 注册；Skill 只选择情绪方向，不下载音乐、不扫描目录、不引用本地文件。
- 用户上传 BGM 时，必须来自稳定、已上传且有授权的引用，例如 `artifact:<id>`、`/artifacts/...` 或 `/uploads/...`。
- 不从外部下载音乐，不读取本地路径，不使用宿主机文件，不要求用户提供命令行文件位置。
- 如果用户要求 BGM 但没有稳定授权音频，先让用户上传音频或确认输出无声版本。
- 如果用户提供人声或旁白，Skill 只描述“需要背景音乐避让人声”的意图；混音、截断、调音量和编码只由 SaaS 后端固定能力处理。
- 如果后端返回 BGM 失败或运行时不可用，诚实说明最终是无声 MP4，不要把“已请求 BGM”说成“已有音乐”。

常用 mood 选择：

- `warm`：邻里、亲情、善意、暖心结尾。
- `gentle`：低冲突、治愈、慢节奏日常。
- `playful`：儿童、亲子、轻喜剧。
- `nostalgic`：旧物、老街、回忆、家庭。
- `calm`：安静陪伴、夜晚、雨天、独处。
- `hopeful`：转机、重逢、被帮助后的明亮收束。

## 预览与渲染边界

外部 Remotion 管线中的分层动画可以作为视觉节奏参考：

- 画面从左到右显现线稿。
- 同一张彩色母图再从左到右填入颜色。
- 每幕末尾保留短暂停顿，方便观众看清完整画面。
- 场景之间硬切，避免用位移动画掩盖母图重复。
- 字幕在顶部安全区进入，不压住人物头部和关键道具。

在当前 SaaS 架构中：

- Skill 不创建 Remotion 工程，不启动 Studio 预览，不运行本地渲染。
- Skill 不运行 FFmpeg 或 ffprobe，也不要求用户复制命令。
- Tool 只提交成片组装意图和稳定素材引用。
- SaaS 后端负责线稿提取、渲染、可用时的 BGM 混音、MP4 校验、artifact 注册和 `agent_artifact` 事件。
- “预览确认”改为对已发布 MP4 artifact 的验收：看时长、尺寸、线稿方向、上色方向、字幕安全区、画面重复度和 BGM 状态。

## 抖音发布文案

当用户要求发布文案、抖音文案、短视频简介或封面标题时，在聊天中输出，不写本地文件。

短标题：

- 不超过 20 个中文字符，尽量 12-15 字。
- 抓住故事里最动人或最反差的瞬间。
- 可以用省略号或问句制造悬念，但不要剧透结局。
- 口语、有温度，不喊口号。

内容文案：

- 2-4 句，总长不超过 80 个中文字符。
- 第一句交代故事起点：谁遇到了什么。
- 第二句留下转折或悬念。
- 最后一句做克制的情绪收束。
- 不说教，不复述完整剧情，不夸大真实事件。

标签：

- 3-5 个话题标签。
- 默认包含 `#原创动画` 和 `#手绘故事`。
- 其余标签从故事主题选择，例如 `#人间温暖`、`#暖心故事`、`#烟火人间`、`#亲子`、`#家庭`、`#校园`、`#邻里`。

输出格式：

```text
标题：……

文案：……

标签：#原创动画 #手绘故事 …
```

## 最终验收清单

- 成片为 720x960、30fps、MP4，总时长 35-45 秒。
- 每幕约 5 秒，节奏包含线稿显现、颜色填入和完整画面停留。
- 线稿和颜色都从左到右推进，起点一致。
- 灰线稿和彩色画面来自同一张母图，人物不会在上色瞬间变脸。
- 全片只使用一种风格，不混用 A/B/C/D/F/G。
- 每幕母图都是独立画面，不用裁切、镜像、换字幕或调色凑新幕。
- 字幕在顶部安全区，最多 3 行，每行约 18 个中文字符。
- 道具文字只在实体道具上，不能把故事正文生成进图里。
- BGM 状态与 Tool 返回一致：没有 BGM、曲库/上传 BGM 已应用，或已降级为无声 MP4。
- Tool 结果和 UI 事件不暴露宿主机路径、临时下载地址或本地输出文件名。
