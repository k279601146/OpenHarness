# Development and GitHub Route

Use this route for public GitHub and open-source ecosystem research.

## Scope

- Public repositories
- README and documentation
- Releases and changelogs
- Public issues and pull requests
- Public discussions
- License and governance signals
- Public code examples

## Process

1. Identify the project or ecosystem.
2. Compare repository purpose, stars/forks when useful, release cadence, recent activity, issue quality, PR health, docs quality, and license.
3. Read public issues and PRs for recurring problems and roadmap signals.
4. Compare alternatives when the user asks for selection advice.
5. Separate evidence from recommendation.

## Output

- Project map
- Activity and maintenance signals
- Strengths and limitations
- Integration risks
- Alternative options
- Recommendation

## Boundary

Do not clone or inspect private repositories unless the user has explicitly provided them in the current workspace with appropriate access. Do not ask for GitHub tokens in chat; higher-rate local access is the user's own environment choice.
