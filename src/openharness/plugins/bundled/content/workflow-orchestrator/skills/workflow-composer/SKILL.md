# Workflow Composer

## 目标

把用户的复杂目标转成可执行工作流，并尽可能直接完成交付。用户应该看到目标、步骤、输入、产物、权限和风险；技能名、市场搜索、插件权限和安装细节默认留在幕后。

这是执行型元技能：负责拆解目标、选择能力、发现缺口、安装确认、串联产物和复盘结果；不替代每个领域技能的具体工作。

## 默认行为

- 默认继续干活，除非需要用户确认或用户明确要求只规划。
- 能用 bundled/official 或已安装能力完成，就不要搜索市场。
- 只有存在能力缺口时，才调用 `skillhub_search_capabilities` 或加载 `find-skill`。
- 安装 SkillHub/市场技能或插件前，必须先调用 `skillhub_prepare_install`，再用 `ask_user_question` 获得确认，最后才调用 `skillhub_install_confirmed`。
- 不执行 SkillHub CLI、不输出 `curl | bash`、不指导用户手动安装；SaaS 安装必须走 marketplace 安全链路。

## 触发边界

只有当请求至少满足以下两项时，才使用完整工作流编排：

- 目标需要多个不同产物，例如文档、表格、图片、网页、PPT、日程、发布文案。
- 用户描述的是生活/工作场景或 outcome，而不是明确的单个工具操作。
- 任务自然包含调研、创作、转换、审校、发布、自动化等多个阶段。
- 步骤之间有依赖关系，例如先调研再写作，先清洗数据再做图表。
- 可能需要从 SkillHub、能力市场或已安装技能中发现额外能力。
- 用户明确说要工作流、方案、pipeline、端到端处理或一整套解决方案。

不要使用完整编排：

- 一个现有技能明显能直接完成任务。
- 用户只是要求快速润色、翻译、少量总结、普通问答或简单头脑风暴。
- 用户已经手动选择技能，并且这些技能足够完成任务。
- 当前最合理动作只是问一个澄清问题，然后执行一个小任务。

不确定时采用轻量模式：给出 2-4 个内部步骤并继续执行，不主动搜索市场，除非执行中发现能力缺口。

## 编排流程

### 1. 判断目标

内部识别：

- 核心结果
- 需要交付的产物
- 受众、语言、风格、截止时间、平台、素材来源等约束
- 是否简单到不需要工作流编排
- 用户是否明确要求只规划、不修改或先讨论

如果用户要求只规划，停在方案层，不安装、不写文件、不调用外部服务。

### 2. 拆解能力步骤

把目标拆成 3-7 个能力步骤。每步包含：

- `intent`：这一步完成什么
- `input`：需要什么输入
- `output`：产出什么
- `depends_on`：依赖哪些前置步骤
- `optional`：是否可以跳过

能并行时使用 DAG 思路，不强行排成线性清单。

### 3. 选择或发现能力

对每个步骤：

- 先检查用户已选择的技能。
- 再检查 bundled/official 和已安装技能。
- 本地能力不够时，用 `skillhub_search_capabilities` 搜索 SkillHub 候选；需要更细的检索策略时加载 `find-skill`。
- 按能力和场景检索，不只按产品名检索。例如搜「social media travel guide copywriting」，而不是只搜「小红书」。

选择最小可行能力集合。不要因为市场上有技能就安装；必须先证明本地能力不够。

### 4. 安装确认

安装任何 SkillHub/市场能力前：

1. 调用 `skillhub_prepare_install` 获取 `confirmation_id`、安装类型和风险。
2. 用 `ask_user_question` 简短说明需要补充的能力、来源、风险，并询问是否安装。
3. 用户确认后调用 `skillhub_install_confirmed`。
4. 安装成功后，继续执行原工作流，不把用户留在安装步骤。

以下情况也必须确认：

- 使用 API key、外部账号、外部服务或付费能力。
- 发布、发送、删除、部署、提交等不可逆动作。
- 工作流存在影响结果的关键歧义。

## 内部工作流对象

内部可使用紧凑结构：

```json
{
  "title": "用户可理解的工作流标题",
  "goal": "具体目标",
  "mode": "execute",
  "steps": [
    {
      "id": "research",
      "intent": "整理目的地信息和路线选项",
      "input": "目的地、天数、预算和偏好",
      "output": "调研笔记和路线候选",
      "selected_capability": "built-in or installed capability",
      "depends_on": [],
      "optional": false
    }
  ],
  "install_required": [],
  "confirm_before": [],
  "blocked_by": [],
  "artifacts": []
}
```

技能名默认留在内部；只有需要用户确认安装、授权或排查时才展示。

## 执行和复盘

- 只有进入某个步骤时，才加载对应技能。
- 明确把上游产物传给下游步骤。
- 给每一步产物命名，方便复用和回溯。
- 如果技能失败，先尝试保守替代方案；仍失败再回到用户。
- 结束时汇总交付物、未解决缺口和可选后续动作。

## 示例

用户说：「我想做一个小红书旅行攻略，包含路线规划、预算表、封面图、正文排版和发布文案。」

应拆成路线、预算、封面、正文、检查一致性几个步骤；先使用已安装和 bundled 能力。若缺少路线规划能力，搜索 SkillHub，选择最匹配候选，安装前确认，安装后继续生成完整攻略，而不是只告诉用户该安装哪个技能。
